| `REWARD_CANCELLED` | consume selected incoming offer/slot, preserve build, no award | Baseline explicitly discards incoming and keeps current relics. |
| `SOURCE_UNAVAILABLE` | `REJECT`, no mutation | A missing or illegal source is not a fallback trigger. |

## Historical 60-gold finding

`openChest` first sets `chest.opened = true`, then routes only `chest.type === "arena_reward"` into `openStoredRelicChest`. That function resolves `chest.relicOfferIds`; only when zero usable relics remain does it call `grantGold(60)`. The literal 60 is independent of depth and is a replacement reward for that existing stored Arena cache, not for the earlier candidate-pool failure. `grantGold` applies `state.runMods.goldMultiplier` and `getPactGoldGainMultiplier()` with `Math.round`, updates player/run/total earned gold, and therefore treats it as an ordinary multiplied gold source. The award occurs after the chest has been closed/consumed.

## Authority and implementation boundary

The client supplies no fallback type, amount, reason, candidate list, source identity, gold delta, or canonical slot. Online v3 derives availability from the bound run, ruleset hash, revision, directive, envelope, reward slot, offer, transaction, build digest, and canonical candidate/stored-choice state. Client-provided `choices`, `emptyPool`, `stale`, `reason`, `sourceId`, or amount fields are rejected.

The Phase 3B2C3A implementation may add a pure evaluator and pure atomic transition, source-specific Warden/Otter policies, and a future Arena fallback specification. It does not issue an Arena offer, connect game code, add an HTTP endpoint, alter D1/recent_ops, or release the ruleset.
