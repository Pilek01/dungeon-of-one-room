# Mobile ergonomics redesign

User grants design discretion; implement directly after the evidence audit.
Work in the existing tree, preserving the uncommitted HD2 assets. No release.

Audit evidence: current screenshots in output/verification/mobile-v2, captured
at 915x412, 844x288 and 390x844. The supplied phone screenshot includes browser
chrome. Current landscape board is 341px at 915x412; D-pad right edge 698px;
HP status is 9px high. Portrait has a large status block and empty vertical gaps.

Design: dark iron, restrained gold, existing game textures/icons, thin frames.
Landscape puts skills at the left thumb and D-pad at the right edge; the board
uses almost the full available height. Persistent survival rails flank it.
Portrait uses a narrow top strip, the board with rails, and two thumb clusters
below. Existing desktop rendering remains scoped out of the new stylesheet.

Implementation sequence:
1. Add portal entry gate with tests, then an accessible native dialog controller.
   Read a presentation model from game.js. Route all decisions through existing
   canonical input keys, retain Ranked checks, existing extraction penalties,
   pending reward flow and automatic bot behavior. No new combat rules.
2. Add mobile-only stylesheet and compact control/header markup. Contextual
   Interact appears only when relevant. The D-pad center remains noninteractive.
   Emergency extraction moves into the run menu, then uses its existing cost
   confirmation. Fullscreen is optional, feature-detected and click-initiated.
3. Capture/test landscape, shortened browser viewport, portrait, tablet and
   desktop. Test portal entry/cancel/reentry, descent, camp, emergency cancel,
   skill arming, menu input blocking, HP/protection rails and fullscreen denial.
4. Run affected mobile regressions, current-tree HD scenario and required
   safety/generator checks. Reuse committed baseline evidence for unchanged HEAD.

Files: index.html, game.js (small adapter), render/mobile-experience.js,
style-mobile-v2.css, focused tests/QA, this plan, audit and progress notes.
Generated source metadata changes are provenance-only; do not activate hashes.

Browser chrome cannot be removed with CSS. Use Fullscreen API where supported;
otherwise keep a correct dynamic-viewport layout and explain Home Screen mode
inside the fullscreen help. Physical phone validation remains a separate limit
of browser emulation.
